# Spec: Docs Refresh & Autogeneration Pipeline

**Track ID:** docs_refresh_20260522
**Type:** Chore / Refactor
**Created:** 2026-05-22

## Overview

The mdBook docs under `docs/src/`, several crate-level READMEs, and the OpenAPI snapshot
have drifted from the current codebase. Major merges since April (microservice decomposition,
gateway-lean, boundaries hardening, events+metrics, SDK rewrite, ScyllaDB segments,
experimentation-full, Rust 1.95 / dep upgrade) invalidated content that was last touched
April 18–22. Some `docs/src/internal/*` files are now orphaned (not referenced by `SUMMARY.md`).

Strategy: **bulk replace by topic** with a tiered autogeneration approach. Lean on generators
wherever there is a code source-of-truth; rewrite narrative prose once against current code;
wire it all into a single `cargo xtask docs` command so future drift becomes a one-command fix.

## Functional Requirements

### FR-1: Autogenerated docs (expand existing pipeline)
- `docs/src/grpc/*` — already generated from `.proto`; keep, verify regeneration runs from xtask.
- `docs/src/gateway/openapi.md` — already wired via `stitchd-gateway --export-openapi`; verify
  current handler set is exported. Delete or archive `docs/openapi-pre-decomposition.json`
  if no longer canonical.
- `docs/src/deployment/env-vars.md` — generate from `STITCHD_*` constant declarations in source.
- **Crate READMEs** under `crates/*/README.md` + `sdks/rust/README.md` — generate via
  `cargo-rdme` from each crate's top-level `//!` rustdoc. Standardize the rustdoc preamble
  in each crate first.
- `docs/src/sdk/quickstart.md` — already auto-extracted from `sdks/rust/src/lib.rs` `//!`
  docs; verify Quickstart section in `lib.rs` is up-to-date instead.

### FR-2: Narrative-prose rewrite (one-shot, against current code)
The following pages need a current-code rewrite (bulk replace by topic):
- `docs/src/introduction.md` — project overview, architecture summary
- `docs/src/architecture/README.md`, `multi-tenancy.md`, `evaluation-flow.md`,
  `data-stores.md`, `events.md`, `metrics.md`, `service-flows.md`
- `docs/src/sdk/README.md` — align to current sdks/ layout
- `docs/src/deployment/README.md`, `postgres.md`, `clickhouse.md`, `scylladb.md`,
  `sdk-keys.md` — current setup; do NOT touch `env-vars.md` (generated)
- `docs/src/gateway/overview.md`, `sdk-api.md`, `admin-api.md`, `grpc.md`
- `docs/src/experimentation/*` — already May 22, spot-check only

### FR-3: Orphaned-doc cleanup
- `docs/src/internal/auth/*`, `docs/src/internal/events-experimentation/*`,
  `docs/src/internal/flag-segmentation/*` — confirmed NOT in `SUMMARY.md`.
  Delete (their content is now covered by per-service generated `grpc/*` docs +
  rewritten architecture pages).
- Investigate `docs/src/api/rest.md` overlap with `docs/src/gateway/openapi.md` and
  collapse/delete if redundant.

### FR-4: Docs build orchestrator
- Extend existing `cargo xtask docs` (in `crates/xtask/src/main.rs`) with:
  1. `protoc-gen-doc`-style proto→md (already wired) → `docs/src/grpc/*`
  2. OpenAPI emit (already wired) → `docs/src/api/openapi.json`
  3. **NEW:** env-vars scraper → `docs/src/deployment/env-vars.md`
  4. **NEW:** `cargo rdme` per crate → updates `crates/*/README.md`
  5. SDK rustdoc + Quickstart extract (already wired)
  6. `mdbook build docs/` (already wired)
  7. **NEW:** internal-link checker (e.g. `mdbook-linkcheck` or simple in-xtask walker)
- Wire to CI as a job that fails if generator output drifts (idempotency gate).

## Non-Functional Requirements
- All commands must be reproducible offline (vendored generators OK; no network at build time
  except for crates.io during `cargo install` of generators).
- mdBook builds with no broken internal links.
- Crate READMEs must be re-runnable idempotently — `cargo rdme` produces no diff on re-run.
- `cargo xtask docs` runs twice → second run produces empty `git status --porcelain`.

## Acceptance Criteria
1. `cargo xtask docs` runs cleanly end-to-end and produces no diff on a second run (idempotent).
2. `mdbook build docs/` succeeds with zero warnings about missing files / broken internal links.
3. Spot-check (manual read-through) of each rewritten narrative page confirms:
   - No references to deleted/renamed crates, modules, or env vars.
   - Architecture diagrams/text match current microservice decomposition.
   - SDK quickstart code matches the current `sdks/rust` crate API surface.
4. `docs/src/internal/*` (orphans) deleted; `SUMMARY.md` unchanged or pruned consistently.
5. All `crates/*/README.md` regenerated from rustdoc; preamble standardized across crates.
6. CI gains a docs job that runs `cargo xtask docs` then `git diff --exit-code` (no drift).
7. CI does not regress (no new failing jobs from generator additions).

## Out of Scope
- New documentation topics that don't already exist (e.g., "Operations Runbook").
- External-facing marketing/landing-page docs.
- Translating docs to other languages.
- Migrating mdBook to a different doc framework (Docusaurus, etc.).
- Auto-publishing the docs site to GitHub Pages / Cloudflare Pages (separate track).
- Generating docs for the React admin UI (separate track if needed).

## Key Risks
- `cargo rdme` may need preamble normalization across many crates — could surface
  inconsistent rustdoc style; in scope to fix.
- env-vars scraper must handle multiple shapes: `std::env::var(...)`, `env::var(...)`,
  constants in `const STITCHD_X: &str = ...`. May surface vars not yet documented.
- Some narrative pages (e.g. multi-tenancy) may have NO current-code source of truth and
  need genuinely written prose, not regeneration.
- Phase 3 parallel workers must respect file-ownership boundaries strictly (per
  `conductor/workflow.md` parallel workflow section).
