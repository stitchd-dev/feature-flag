# Codebase Patterns

Reusable patterns discovered during development. Read this before starting new work.

## Code Conventions

- Rust 2024 edition requires `resolver = "3"` in workspace `Cargo.toml` (not `"2"`). (from: scaffold_20260411, 2026-04-11)
- `std::env::set_var` is **unsafe** in Rust 2024 — always wrap in `unsafe {}` with a `// SAFETY:` comment, even in build scripts. (from: scaffold_20260411, 2026-04-11)
- `rustfmt.toml` options like `imports_granularity`, `group_imports`, `wrap_comments`, `normalize_comments` are **nightly-only** — they silently no-op on stable without error. Strip them from stable configs. (from: scaffold_20260411, 2026-04-11)

## Architecture

- **Prometheus metrics:** Use `PrometheusBuilder::new().install_recorder()` to get a `PrometheusHandle`. Pass it as Axum `State` and call `handle.render()` in the `/metrics` route handler. (from: scaffold_20260411, 2026-04-11)
- **Graceful shutdown:** Use `tokio::select!` over `ctrl_c()` + `SIGTERM` (gated `#[cfg(unix)]`) as the shutdown signal. Pass to `axum::serve(...).with_graceful_shutdown(...)`. (from: scaffold_20260411, 2026-04-11)
- **Vendored protoc:** Add `protoc-bin-vendored` as a build dependency in `stitchd-proto` and set `PROTOC` env var in `build.rs`. Eliminates system `protoc` requirement for all contributors and CI. (from: scaffold_20260411, 2026-04-11)
- **API Error Mapping:** Implement `IntoResponse` for a custom `ApiError` enum that maps internal errors (Repository, Validation, etc.) to HTTP status codes. (from: segmentation_20260412, 2026-04-12)
- **Axum 0.8 Routing:** Use `{param}` syntax for path captures (e.g., `/users/{id}`) as Axum 0.8 deprecated the `:param` style. (from: fix_errors_20260412, 2026-04-12)
- **In-process cache primitive:** Use `moka::future::Cache<K, V>` with `time_to_live` for in-process caching. Call `.get_or_try_insert_with(key, loader)` — concurrent callers for the same key coalesce to a single loader invocation. Invalidate explicitly (e.g., on revocation) with `.invalidate(&key).await`. (from: db_optim_20260516, archived 2026-05-16)
- **Pagination total without second query:** Use `COUNT(*) OVER()` window function alongside `SELECT` columns — returns the total row count in every result row, eliminating a separate `SELECT COUNT(*)` round-trip. Pull `total` from `row.total` (type `i64`) and cast to `u64`. (from: db_optim_20260516, archived 2026-05-16)

## Rust 2024 Edition Patterns

- When iterating a `HashMap` and only needing keys or values, use `.keys()` / `.values()` — `for (k, _) in map` triggers `clippy::for_kv_map` as a warning-level error with `-D warnings`. (from: rule_engine_20260412, 2026-04-12)
- In filter closures over iterator references (e.g. `.filter(|(_, d)| ...)`), the value `d` is `&&T` — dereference with `**d` or use `.filter(|&(_, d)| ...)`. Pattern-binding `&d` inside a non-reference outer pattern fails in Rust 2024. (from: rule_engine_20260412, 2026-04-12)
- **ID Newtypes:** Use `macro_rules!` to define repetitive UUID-based newtypes with `sqlx::Type(transparent)` to minimize boilerplate. (from: domain_20260411, 2026-04-11)
- **Type Dispatch:** `matches!` macro with tuple patterns is the cleanest way to express multi-arm type dispatch (e.g., `matches!((val, type), (Variant::Int(_), Type::Int))`). (from: domain_20260411, 2026-04-11)
- **Wildcard Matching:** Use `strip_suffix('*')` for simple prefix-based wildcard matching without the overhead of regex. (from: domain_20260411, 2026-04-11)

## Auth Patterns

- **Enum privilege ordering:** Define role enum variants low-privilege first so `#[derive(Ord)]` gives higher-numbered variants more privilege. E.g., `OrgMember=0, OrgAdmin=1` → `OrgAdmin > OrgMember` without custom `PartialOrd`. (from: auth_20260421, 2026-04-21)
- **sqlx enum DB mapping:** `#[sqlx(rename_all = "snake_case")]` on an enum with `sqlx::Type` maps Rust `PascalCase` variants to `snake_case` in the DB CHECK constraint values automatically. (from: auth_20260421, 2026-04-21)
- **ID type name:** The org identifier type is `OrganisationId` (not `OrgId`) — always check actual type names in `crates/stitchd-core/src/id.rs` before using. (from: auth_20260421, 2026-04-21)
- **Rate limiting pattern:** `governor` + `tower_governor` with a `SmartIpKeyExtractor` that reads `x-forwarded-for` → `x-real-ip` → peer address in that order to correctly key per-client behind a reverse proxy. (from: auth_20260421, 2026-04-21)

## Gotchas

- `clickhouse` crate v0.13 has no `derive` feature — use `uuid`, `time`, `lz4` features instead. (from: scaffold_20260411, 2026-04-11)
- **SQLx Offline Compilation:** `sqlx::query!` macros require a live DB or up-to-date `.sqlx` cache. New queries will break compilation in offline mode until `cargo sqlx prepare` is executed. (from: segmentation_20260412, 2026-04-12)
- **Database Extension Dependencies:** Call functions from extensions (like `pg_partman`) using plain `sqlx::query` to avoid macro-based compilation errors when extensions aren't available in the local build environment. (from: segmentation_20260412, 2026-04-12)
- **OpenTelemetry version alignment:** `tracing-opentelemetry 0.29` requires `opentelemetry ^0.28`. `opentelemetry-otlp 0.27` requires `opentelemetry ^0.27`. These produce **incompatible types** — pin all OTel crates to the same minor version. (from: scaffold_20260411, 2026-04-11)
- `opentelemetry_sdk 0.28` made `Resource::new()` private. Use `Resource::builder()` — confirm exact builder API before wiring OTLP in the observability track. (from: scaffold_20260411, 2026-04-11)
- **Recursive Types:** Recursive enums or structs (like expression trees) must use `Box<T>` for recursive variants to avoid infinite-size type errors. (from: rule_engine_20260412, 2026-04-12)
- **SQLx CLI Installation:** Use `--no-default-features --features rustls,postgres` when installing `sqlx-cli` to avoid unnecessary system dependencies like OpenSSL. (from: domain_20260411, 2026-04-11)
- **Integer Truncation:** Rust 2024 lints against implicit/risky conversions; `as i32` on `usize` should be avoided or handled with `try_into()` if overflow is possible. (from: fix_errors_20260412, 2026-04-12)
- **`CREATE INDEX CONCURRENTLY` inside a transaction:** sqlx migrations wrap each file in a transaction by default. `CREATE INDEX CONCURRENTLY` cannot run inside a transaction and will error. Either split the index into its own migration file (sqlx wraps each file separately) or add `-- migrate:noTransaction` at the top. For production, run `CREATE INDEX CONCURRENTLY` manually outside a migration to avoid table locks. (from: db_optim_20260516, archived 2026-05-16)
- **`serde_urlencoded` + `#[serde(flatten)]` + `u32`:** Axum's `Query<T>` extractor uses `serde_urlencoded`, which passes all query param values as strings. A `u32` field inside a `#[serde(flatten)]` struct will fail deserialization with "invalid type: string '1', expected u32". Add a custom visitor that calls `deserialize_any` and accepts both integer and string representations. (from: db_optim_20260516, archived 2026-05-16)
- **`STITCHD_DATABASE_URL` vs `DATABASE_URL`:** The project uses `STITCHD_DATABASE_URL` as the canonical env var; however, `sqlx-cli` and `cargo sqlx prepare` require a plain `DATABASE_URL`. Always export both or alias: `export DATABASE_URL="$STITCHD_DATABASE_URL"` in the shell session before running sqlx commands. (from: boundaries_20260518, 2026-05-19)
- **`--no-ff` merge + `git branch -d` fails for diverged worker branches:** After merging a worker's branch with `--no-ff`, `git branch -d` refuses because the worker branch is not in a fast-forward ancestor relationship. Use `-D` once the worker SHA is confirmed in the target branch history via `git log --oneline target/... ^main`. (from: boundaries_20260518, 2026-05-19)
- **`git checkout --ours <path>` leaves the file unmerged:** Checking out `--ours` during a merge keeps HEAD content but the file stays in an unmerged state until `git add <path>` is explicitly run. (from: boundaries_20260518, 2026-05-19)
- **Discovered out-of-scope work: file as beads bug, don't fix inline:** When a worker finds a pre-existing issue clearly outside the current task scope, file a new beads bug with priority 2 and reference it from the report-back. Do not fix it inline — doing so makes the PR diff harder to review and the fix may conflict with upcoming planned work. (from: boundaries_20260518, 2026-05-19)
- **E2E infra-dependent tests need explicit `#[ignore]`:** Tests that require a running service daemon (e.g. `evaluate_preview_writes_rows_to_clickhouse` needing flag-service on `:50052`) must be marked `#[ignore = "needs running flag-service daemon"]`. Without the annotation, setting `FLAG_SERVICE_ADDR` in `.env.local` causes the test to attempt a real connection and fail silently in CI. (from: boundaries_20260518, 2026-05-19)

## Testing

- Axum router integration tests: use `tower::ServiceExt::oneshot` to send a single request through the router without starting a real TCP server. Add `tower` as a `[dev-dependencies]` entry. (from: scaffold_20260411, 2026-04-11)
- **Isolated DB Testing:** `#[sqlx::test(migrations = "./migrations")]` is the idiomatic way to run fast, isolated database tests with automatic migration handling in SQLx 0.8. (from: domain_20260411, 2026-04-11)
- **`cargo sqlx prepare` skips `#[cfg(test)]`:** Test-only queries are NOT captured by `cargo sqlx prepare` (which runs `cargo check`, not `cargo test`). Always compile tests against a live `DATABASE_URL`, never `SQLX_OFFLINE=true`. (from: scheduled_stats_20260423, archived 2026-04-23)
- **`cargo sqlx prepare` deletes cached test queries:** Re-running `cargo sqlx prepare` may remove previously-cached test-only query entries. Verify test compilation with a live DB after every `prepare` run. (from: scheduled_stats_20260423, archived 2026-04-23)
- **`sqlx::query_as` for new tables:** New repository modules should use `sqlx::query_as::<_, Row>(r"...")` raw strings instead of `sqlx::query!` macros to avoid offline compilation failures when the `.sqlx` cache hasn't been populated for a new table yet. (from: scheduled_stats_20260423, archived 2026-04-23)
- **Local `DATABASE_URL` for `#[sqlx::test]`:** Use `postgresql://stitchd:stitchd@localhost:5432/stitchd` (TCP). Socket-auth URLs (e.g. `postgresql://vishal@localhost/stitchd`) fail because `#[sqlx::test]` always connects over TCP. (from: scheduled_stats_20260423, archived 2026-04-23)
- **Test env-var isolation:** Config tests and sqlx tests share the same binary. Use `--test-threads=1` and an `EnvGuard` RAII wrapper to prevent env-var contamination across test cases. (from: scheduled_stats_20260423, archived 2026-04-23)
- **In-process tonic mock servers for integration tests:** Bind `tokio::net::TcpListener::bind("127.0.0.1:0")` for a random free port; wrap with `tokio_stream::wrappers::TcpListenerStream`; pass to `tonic::transport::Server::builder().serve_with_incoming(...)` in a `tokio::spawn`. Client connects to `format!("http://{}", listener.local_addr()?)`. No external mocking library, no port conflicts. (from: boundaries_20260518, 2026-05-19)
- **Per-crate `cargo test -p <crate>` over `cargo test --workspace`:** Running per-crate gives cleaner signal when a single crate breaks — workspace parallelism can intermix output. Use per-crate invocations during verification passes; use workspace for final CI-mirror checks. (from: boundaries_20260518, 2026-05-19)
- **`--features test-util` required for SDK clippy `--all-targets`:** `cargo clippy -p stitchd-sdk-rust --all-targets` fails with unresolved imports unless `--features test-util` is passed — conformance test helpers are behind that feature gate. (from: boundaries_20260518, 2026-05-19)
- **`.sqlx/` offline cache may be clean even when a repo module is deleted:** Repos that used `sqlx::query_as::<_, Row>(r"...")` raw strings (not `sqlx::query!` macros) leave no entries in `.sqlx/`. Grep the cache before assuming regeneration is mandatory on deletion. (from: boundaries_20260518, 2026-05-19)
- **Scylla perf tests must be `#[ignore]`d by default:** `perf_40_segments_1m_entries_each` writes 40 M rows and runs for minutes. Mark with `#[ignore]`; opt in with `cargo test -p stitchd-db --test scylla_perf_e2e -- --ignored`. (from: boundaries_20260518, 2026-05-19)
- **`cargo clippy --workspace --all-targets --fix --allow-dirty -- -D warnings` is a safe batch fix:** A single pass resolves the majority of accumulated lint families (`useless_format`, `approx_constant`, `cast_lossless`, `assert_eq!(x, bool_literal)`). Auto-fix applies `#[allow(clippy::result_large_err)]` with a justification comment for tonic return types where boxing would change the public API. (from: boundaries_20260518, 2026-05-19)

## ClickHouse

- **AggregatingMergeTree insert/read combiners:** When writing to an `AggregatingMergeTree`, use `*State` combiners (`sumState`, `countState`, `uniqState`) in INSERT...SELECT. When reading, use `*Merge` combiners (`sumMerge`, `countMerge`, `uniqMerge`) in GROUP BY queries — NOT `finalizeAggregation`, which is a scalar function and fails in aggregated context. (from: db_optim_20260516, archived 2026-05-16)
- **`sumState(Nullable(Float64))` type mismatch:** `sumState` applied to a `Nullable(Float64)` expression produces `AggregateFunction(sum, Nullable(Float64))`. If the target column is declared `AggregateFunction(sum, Float64)` (non-nullable), the insert fails. Wrap the input with `ifNull(expr, 0.0)` to coerce to `Float64` before calling `sumState`. (from: db_optim_20260516, archived 2026-05-16)
- **Weekly ClickHouse partition key:** Use `toMonday(event_date)` as the partition expression to get weekly partitions keyed to Mondays. Combine with `TTL toMonday(event_date) + INTERVAL 52 WEEK` for year-length retention windows. (from: db_optim_20260516, archived 2026-05-16)

## Frontend (Admin UI) Patterns

- **`verbatimModuleSyntax`:** Vite + TypeScript projects with `verbatimModuleSyntax: true` require `import type { Foo }` for any type-only import — a plain `import { Foo }` triggers TS1484. Always use the `type` keyword for types, interfaces, and enums not used as values. (from: admin_ui_20260427, archived 2026-04-28)
- **Gateway API shapes are minimal:** The gateway's JSON responses contain only the fields needed by the SDK evaluation path (e.g., `FlagJson` only has `key` + `enabled`). Any admin UI displaying richer data (owner, sparklines, segments, variants) must use mock data or a dedicated admin API. (from: admin_ui_20260427, archived 2026-04-28)
- **react-refresh ESLint rule:** Files that export both components and non-component values (maps, constants, type aliases) trigger `react-refresh/only-export-components`. Fix by either moving the non-component export to a separate file, or adding `// eslint-disable-next-line react-refresh/only-export-components` on that export line. (from: admin_ui_20260427, archived 2026-04-28)
- **TypeScript CLI in Vite projects:** Never run `npx tsc` — it resolves to a stray `tsc` package (2.0.x). Always use `node_modules/.bin/tsc --noEmit -p tsconfig.app.json` with the full absolute path to the admin directory as CWD. (from: admin_ui_20260427, archived 2026-04-28)
- **Vite dev proxy for gateway:** Admin UI uses `vite.config.ts` server proxy: `/api → http://localhost:8080` with `changeOrigin: true` and path rewrite stripping the `/api` prefix. Set `VITE_API_BASE_URL` in `.env` for production builds pointing directly at the gateway. (from: admin_ui_20260427, archived 2026-04-28)
- **`useParams` vs `pathname` for route context disambiguation:** `useParams` fires `orgId` on both `/org/:orgId` and `/superadmin/orgs/:orgId`. Use `location.pathname.startsWith('/org/')` to distinguish superadmin from org context when computing nav items, guards, or section-scoped behaviour. (from: admin_ui_multitenant_20260428, archived 2026-04-29)
- **Seamless org switching via dedicated RPC:** For JWT-scoped org auth, implement a `SwitchOrg` RPC that validates the current token, verifies target-org membership, and issues a fresh JWT — no password re-entry. The response intentionally omits `user_id`; callers must preserve it from the existing session to avoid corrupting the session store. (from: admin_ui_multitenant_20260428, archived 2026-04-29)
- **Multi-tenant user seeding (find-or-create):** Users are globally unique by email. Seeding a user into an org uses find-or-create semantics: look up by email first; if found, just add the org membership (idempotent on duplicate); only create a new record when the email doesn't exist. Do NOT drop the unique email constraint. (from: admin_ui_multitenant_20260428, archived 2026-04-29)
- **ListUserOrgs should filter system orgs:** The `ListUserOrgs` RPC (and the gateway route it backs) must exclude system-org entries (`is_system=true`) to prevent the internal "System" org from appearing in user-facing org-switcher dropdowns. (from: admin_ui_multitenant_20260428, archived 2026-04-29)
- **RBAC permissions must be expanded from role — not left empty:** `rbac_context_from_jwt` defaults to `permissions: vec![]`. Role→permission expansion must be done explicitly in `crates/stitchd-auth-service/src/rbac.rs`. Current policy: `org_admin` → all 9 management permissions; `org_member` → `["environment:read"]` only. (from: env_sdk_rbac_20260429, archived 2026-04-29)
- **`require_non_system_org` middleware guards mgmt_routes:** Management routes in `router.rs` sit behind both JWT auth and `require_non_system_org`. Superadmin users (`is_system=true`) are intentionally blocked — they must use `/superadmin/*` routes. Never put management handlers in the public or system-only route trees. (from: env_sdk_rbac_20260429, archived 2026-04-29)
- **`get_my_permissions` must be in `resource_routes`, not public `auth_routes`:** The handler extracts `RbacContext` via `Extension<RbacContext>`. This extension is only injected by `auth_middleware`, which only runs on `resource_routes`. Placing it in the public router causes Axum to return 500 (extractor not found). (from: env_sdk_rbac_20260429, archived 2026-04-29)
- **Sidebar picker pattern (OrgSwitcher / ProjectPicker / EnvSwitcher):** All sidebar entity pickers share one visual pattern: trigger button using `.org-switcher` + `.org-avatar` + `.org-meta` + `.org-name` + `.org-chevron`; dropdown with "Switch to" label, `.sidebar-link` rows, checkmark on active item, outside-click-to-close via `useRef` + `mousedown` listener. New pickers should reuse these classes for visual consistency. (from: env_sdk_rbac_20260429, archived 2026-04-29)
- **RBAC UI gating pattern:** Use `disabled` + `style={{ opacity: 0.35 }}` (never `display:none`) for actions the user lacks permission for — keeps affordances visible. For zero read access, render a full `LockOverlay` over the section. Seed `usePermissions()` from JWT claims on mount (fast render), then fetch `/v1/auth/me/permissions` for the authoritative view. (from: env_sdk_rbac_20260429, archived 2026-04-29)
- **EnvSwitcher / ProjectPicker stale-ID fallback:** After a project switch, `envId` in localStorage may not match any environment in the new project. Always fall back to `environments[0]` when the lookup fails, and sync state back via a `useEffect` guard. Use functional `setState(prev => ...)` inside async `.then()` to avoid stale-closure races. (from: env_sdk_rbac_20260429, archived 2026-04-29)
- **Cargo must run from the worktree root:** Running `cargo test/clippy` from the main repo root compiles the main branch, silently ignoring worktree changes. Always `cd .worktrees/<track_id>/` or pass `-C <worktree_path>` before any Cargo command when working in a worktree. (from: env_sdk_rbac_20260429, archived 2026-04-29)
- **Domain model change order:** When adding a field to a domain type, always follow the chain: `stitchd-core` structs → DB repo queries → flag/domain service → proto definition → proto mapping (`mapping.rs`) → gateway handler. Skipping steps causes compile errors deep in the chain. (from: flags_crud_20260512, archived 2026-05-12)
- **Formik + Yup is the only form pattern in admin UI:** All admin forms use `<Formik>` + Yup schema. Never use ad-hoc `useState` for form field state. Primitives are in `admin/src/components/form/`; schemas go in `admin/src/lib/validation/`. API errors surface via `formik.setStatus({ error: message })`, rendered by `<FormErrorBanner />`. (from: boundaries_20260518, 2026-05-19)
- **`validateOnChange={false}` for async Yup validators:** When using async `.test()` validators (e.g. flag-key uniqueness check), always set `validateOnChange={false}` on `<Formik>` to prevent an API call on every keystroke. Trigger validation on blur or submit only. (from: boundaries_20260518, 2026-05-19)
- **`FormCheckbox` field spread:** Formik's `useField({name, type:'checkbox'})` returns `value: boolean`. Spread `name`, `checked`, `onChange`, `onBlur` individually instead of `{...field}` — the `value: boolean` vs `value: string` HTMLInput type conflict causes unexpected checkbox behaviour. (from: boundaries_20260518, 2026-05-19)
- **`enableReinitialize` for async-loaded edit forms:** When form `initialValues` depend on async-loaded data (e.g. an edit modal that re-fetches from API before showing), add `enableReinitialize` to `<Formik>`. Without it, Formik ignores `initialValues` changes after first render. (from: boundaries_20260518, 2026-05-19)
- **`key={mode}` for mode-switching Formik forms:** When a single form switches between modes (e.g. create vs edit, or existing/new user), add `key={mode}` to the `<Formik>` element to force a full remount and reset validation state. (from: boundaries_20260518, 2026-05-19)
- **Admin UI modal primitives (`Modal`, `Dropdown`, `EmptyState`):** Reusable layout primitives are in `admin/src/components/`. Always use existing modal, dropdown, and empty-state primitives for consistency — do not create one-off implementations per feature page. (from: boundaries_20260518, 2026-05-19)
- **Proto condition payload:** `rule_payload` in `FlagRule` is `serde_json::to_vec(&ConditionExpr)` — a JSON-encoded condition tree stored as bytes. In the gateway admin API, deserialize with `serde_json::from_slice` and pass through as `serde_json::Value`; no custom schema decoding needed. (from: flags_crud_20260512, archived 2026-05-12)
- **Admin vs SDK response shape:** Always define a separate `AdminFooJson` struct in the gateway for admin UI responses (full data: name, description, variants, rules, version, timestamps). The SDK-facing `FooJson` must stay minimal for performance. Never bloat the SDK response to satisfy UI needs. (from: flags_crud_20260512, archived 2026-05-12)
- **Bool-type flag invariant:** Boolean flags always have exactly 2 variants with fixed values `true` and `false`. Enforce this at both layers: gateway `update_variants` returns HTTP 400 if count ≠ 2 or values aren't `{true, false}`; UI hides Add/Remove controls and shows values as read-only. (from: flags_crud_20260512, archived 2026-05-12)
- **Gateway is the sole SDK trust boundary:** Backend services NEVER validate SDK keys — they trust the `x-env-id` gRPC metadata header propagated by the gateway after successful SDK key validation. Backends must reject requests missing this header with `Unauthenticated`. Never pass the raw SDK key to backend services. (from: sdk_rewrite_20260516, archived 2026-05-16)
- **Lazy-on-miss LRU with filtered background refresh:** Create LRU entries only on the first `evaluate()` miss for a `(context_type, key)`. Background refresh must only request memberships for context keys already resident in the LRU AND segments currently referenced by flag definitions — never poll segments not in active use. (from: sdk_rewrite_20260516, archived 2026-05-16)
- **gRPC service registration gotcha:** Implementing a tonic service trait (`impl XxxService for Impl`) is not sufficient — the service MUST also be registered via `.add_service(XxxServiceServer::new(impl_))` in `main.rs`. Unregistered services return `Unimplemented` with no startup warning. Always audit `main.rs` after adding a new `impl XxxService`. (from: sdk_rewrite_20260516, archived 2026-05-16)
- **ClickHouse credentials required at startup:** Services that write to ClickHouse must be started with `CLICKHOUSE_USER=stitchd CLICKHOUSE_PASSWORD=stitchd CLICKHOUSE_DB=stitchd`. The ClickHouse-rs client defaults to `user=default` with no password, which fails auth and causes 502 from the gateway with no clear message. (from: sdk_rewrite_20260516, archived 2026-05-16)
- **Stale worktree binary on shared port:** When restarting services for testing after a new build, verify with `ps -o comm=` that the binary serving a port is the one from the current worktree. Old binaries from previous tracks may still be listening and will silently lack new gRPC methods, returning `Unimplemented`. (from: sdk_rewrite_20260516, archived 2026-05-16)

## ScyllaDB

- **CQL TIMESTAMP type mapping:** Use `scylla::value::CqlTimestamp(millis_i64)` for TIMESTAMP columns — NOT raw `i64` or `chrono::DateTime`. Passing the wrong type produces a driver-level type error at runtime, not compile time. (from: segment_scylla_20260516, archived 2026-05-18)
- **Random generation IDs prevent CAS collisions:** In generation-swap CAS patterns (INSERT IF NOT EXISTS with a `(segment_id, generation)` key), always use a random i64 (e.g., `rand::random::<i64>()`) rather than `current_gen + 1`. Sequential IDs cause silent data merging: two concurrent writers both compute `next = 1`, both CAS succeed on different replicas, and their entries coexist in the same partition. (from: segment_scylla_20260516, archived 2026-05-18)
- **`gen` is a reserved keyword in Rust:** Do not use `gen` as a variable name for generation IDs — it is reserved in Rust 2024. Use `active_gen`, `cur_gen`, or `generation` instead. (from: segment_scylla_20260516, archived 2026-05-18)
- **ScyllaDB direct deps are in `stitchd-db` only:** Only `stitchd-db` (library) and `stitchd-segmentation-service` (consumer) have direct `scylla` crate dependencies. Other crates referencing ScyllaDB data go through the DB repository layer. Verify with `scripts/check_scylla_containment.sh`. (from: boundaries_20260518, 2026-05-19)

## Gateway

- **JSON/payload body size limit:** Axum's default body size limit is 2 MB. Bulk import endpoints that receive large payloads (e.g., CSV-sourced key lists serialised as JSON) should set an explicit limit via `DefaultBodyLimit::max(bytes)` layer — or use chunked streaming to avoid buffering the full body in memory. (from: segment_scylla_20260516, archived 2026-05-18; corrected: boundaries_20260518, 2026-05-19)
- **Gateway lean principle:** When the gateway accumulates direct DB clients (ClickHouse, Postgres) or domain logic beyond auth+routing, extract those into a dedicated analytics/aggregation service. The gateway should only hold gRPC client channels. Direct DB deps in the gateway signal a service boundary violation. (from: gateway_lean_20260518, archived 2026-05-18)
- **Fire-and-forget gRPC for analytics:** Use `tokio::spawn` for non-critical analytics/telemetry gRPC calls (e.g. `RegisterContext` upserts). Log errors but don't propagate them — callers should never block on telemetry side-effects. (from: gateway_lean_20260518, archived 2026-05-18)
- **Shared `require_permission` in `routes/mod.rs`:** Extract repeated permission-checking helpers to the route module root (`routes/mod.rs`). All sub-modules use `super::require_permission` — prevents copy-paste drift and keeps the auth logic in one place. (from: gateway_lean_20260518, archived 2026-05-18)
- **Proto JSON-string fields need explicit deserialization at consumers:** Proto fields that carry JSON payloads (e.g. `ExperimentResult.variant_stats`) are wire-level `String`, not `serde_json::Value`. Consumer code that previously read these as `Value` from PostgreSQL must call `serde_json::from_str` explicitly at the gRPC boundary. (from: boundaries_20260518, 2026-05-19)
- **`tonic::Channel` is `Clone` and cheap to clone:** The underlying `Channel` type clones cheaply (shares the connection pool). Prefer cloning the `Channel` and creating per-task clients rather than wrapping a single client in `Arc<Mutex<...>>`. (from: boundaries_20260518, 2026-05-19)
- **tonic-generated client paths use `*_service_client` submodule:** When importing tonic-generated clients, the full path is `stitchd_proto::analytics::v1::analytics_service_client::AnalyticsServiceClient` — not re-exported at `v1::`. Likewise, service traits used by hand-rolled servers live under `*_service_server::*ServiceTrait`. (from: boundaries_20260518, 2026-05-19)

## Events + Metrics Patterns

- **Discriminated-union serde + protobuf oneof alignment:** Tagged-union Rust enums (e.g. `MetricKind`) using `#[serde(tag = "kind", rename_all = "snake_case")]` embed cleanly inside a parent struct via `#[serde(flatten)]` — the top-level JSON gets the `kind` discriminator inline, matching the protobuf `oneof` wire format exactly. No domain↔proto mapping layer needed. (from: events_metrics_20260519, archived 2026-05-20)
- **Adding tonic RPCs breaks every impl — fix MockServices too:** Adding a method to a tonic service trait is a workspace-wide compile error. Always grep `impl <Service> for` and add `Unimplemented` stubs to in-process MockServices in tests at the same time, or `cargo test --workspace` breaks. (from: events_metrics_20260519, archived 2026-05-20)
- **`toFloat64OrNull` only accepts String:** ClickHouse's `toFloat64OrNull(...)` errors at runtime with `ILLEGAL_TYPE_OF_ARGUMENT` if the input is already `Float64` (e.g. `coalesce(value_double, value_int)`). Use it ONLY to coerce `properties['<key>']` (String) to Float64; for native numeric columns skip the wrapper and rely on `ifNull(coalesce(...), 0.0)`. (from: events_metrics_20260519, archived 2026-05-20)
- **`clickhouse-rs` binds `?` placeholders by SQL position, not vec index:** The `{p0}` → `?` rewriter rewrites the SQL string but does NOT reorder the parallel bind vec. If a SQL emits `{p5}` (a later push) before `{p0}` (an earlier push), the values bind to the wrong placeholders and you get cryptic errors like `Cannot parse uuid <step-event-key>`. Push binds in SQL-appearance order to keep the contract sound. (from: events_metrics_20260519, archived 2026-05-20)
- **Proto field deprecation needs `reserved`:** When removing a field tag from a proto message, add `reserved <N>;` and `reserved "<old_field_name>";` so a future field can never repurpose the tag or name (wire-compat hygiene). Example: `reserved 2, 3; reserved "context_type", "context_key";` after deleting the singular context pair from `TrackEvent`. (from: events_metrics_20260519, archived 2026-05-20)
- **`Count` metric_type is an occurrence marker:** Events registered with `metric_type = Count` should accept missing `value` at ingestion. The `count()` aggregator ignores the value column and SDKs (e.g. admin's TestEventWidget) omit value for count events. Special-case the validator: `(_, None) if def.metric_type == Count => (None, None, None)`. Other metric_types retain strict value requirements. (from: events_metrics_20260519, archived 2026-05-20)

## Dependency / Toolchain Upgrade Patterns

- **`major.minor` is the workspace canon, never bare-major or patch:** Every entry in `[workspace.dependencies]` is pinned to `major.minor` (e.g. `tokio = "1.52"`, `tonic = "0.14"`). Bare-major (`"1"`) is too permissive; patch pins (`"0.24.6"`) churn the lockfile on transitives. After bumping, normalise by reading the regenerated `Cargo.lock` and writing `<crate> = "<major>.<minor>"`. (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **Rust toolchain stays on `stable` in BOTH places — never pin:** `rust-toolchain.toml` keeps `channel = "stable"` and every `dtolnay/rust-toolchain@stable` reference in `.github/workflows/*.yml` stays on `@stable`. The declarative MSRV in `[workspace.package].rust-version` (e.g. `"1.95"`) is the sole "Rust X.Y" enforcement point. CI then auto-picks up new stable releases. (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **`cargo upgrade --incompatible --pinned` + `cargo generate-lockfile` is the cleanest bump path:** `cargo-edit`'s `--pinned` flag overrides the safety default that skips bare-major specs; the regenerate step bypasses `cargo update`'s MSRV-aware resolver that can otherwise hold things back. (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **`tonic 0.13 → 0.14` is a codec split:** v0.14 separates the codec from the build/runtime crates — add `tonic-prost` (runtime) + `tonic-prost-build` (build) to workspace deps and to each crate that compiles `.proto` files. `tonic_build::configure()` no longer exists; use `tonic_prost_build::configure()`. `compile_protos` now takes `&[PathBuf, ...]`, not `&[&PathBuf, ...]`. The `tonic::include_proto!` macro still works. (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **`clickhouse 0.15` made `Client::insert()` async + generic over `<Row>`:** Every `client.insert("table")?` becomes `client.insert::<Row>("table").await?`. The Row type must be specified explicitly; type inference fails because `Insert<_>: Row` is ambiguous. (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **`openidconnect 4` flipped to endpoint type-state:** After `from_provider_metadata`, the client carries `EndpointSet` for auth_url and `EndpointMaybeSet` for token/userinfo. The default `CoreClient` alias has `EndpointNotSet` for all four and won't store the post-discovery shape. Declare a `pub type OidcDiscoveredClient = CoreClient<EndpointSet, EndpointNotSet, EndpointNotSet, EndpointNotSet, EndpointMaybeSet, EndpointMaybeSet>` alias. The async http client is passed by reference (`&Client`) to `discover_async` / `request_async`, not as a closure. `exchange_code` on `EndpointMaybeSet` returns `Result<CodeTokenRequest, ConfigurationError>` — unwrap before `.set_pkce_verifier(...)`. (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **`oauth2 5` pulls reqwest 0.12, workspace uses 0.13 — two `reqwest::Error` types coexist:** The transitive duplication is benign but the two error types are distinct. Keep `OidcError::Http(#[from] reqwest::Error)` bound to the workspace 0.13 version (used in the GitHub OAuth path) and convert openidconnect-side HTTP errors via `String`-wrapped variants (`OidcError::Discovery`, `OidcError::TokenExchange`). (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **`rand 0.10` migration:** `rand::thread_rng()` → `rand::rng()`; `rng.gen_range(...)` → `rng.random_range(...)`; `use rand::RngCore` → `use rand::Rng`. High-level helpers like `random_range` live on `rand::RngExt` (auto-impl for any `Rng`). (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **`reqwest 0.13` feature rename + `form`/`http2` no longer in default:** With `default-features = false`, the `rustls-tls` feature is now just `rustls`; `form` (urlencoded body support) and `http2` must be opted into explicitly. (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **`aes-gcm 0.10` + `-D warnings` rejects deprecated GenericArray helpers:** `Key::from_slice`, `Nonce::from_slice`, `nonce.as_slice()` emit `deprecated`. Workaround: use `Aes256Gcm::new_from_slice(&[u8; 32])` and convert `[u8; 12] ↔ Nonce<U12>` via the `From` impl (`nonce_bytes.into()`). Pick the nonce bytes via `rand::rng().fill_bytes(&mut [0u8; 12])`. (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **`sha2 0.11` digest no longer implements `LowerHex`:** `format!("{digest:x}")` breaks; use `hex::encode(digest)` for the same hex output. (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **Rust 1.95 clippy adds `collapsible_if` for let-chains:** Nested `if let A { if B { ... } }` becomes `if let A && B { ... }` with Rust 2024 let-chains. With workspace `-D warnings`, every site is a hard error. (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **Rust 1.95 clippy adds `duration_suboptimal_units`:** `Duration::from_secs(60)` → `from_mins(1)`; `from_secs(3600)` → `from_hours(1)`; `from_secs(24 * 3600)` → `from_hours(24)`. `from_mins`/`from_hours`/`from_days` are stable since Rust 1.81. (from: rust_deps_upgrade_20260520, archived 2026-05-20)
- **`clippy.toml` MSRV must track `Cargo.toml`:** A mismatch emits "MSRV in clippy.toml and Cargo.toml differ" and clippy then uses the *lower* of the two for available-lint detection. Bump them together. (from: rust_deps_upgrade_20260520, archived 2026-05-20)

## Experimentation Patterns

- **CH dictionary refresh from PG source on lifecycle transitions:** When a CH dictionary mirrors a PG table on the hot path (e.g. `experiment_iterations_active`), declare it with `LIFETIME(MIN 300 MAX 600)` *and* fire `SYSTEM RELOAD DICTIONARY <name>` explicitly on every PG row change. Polling-only refresh introduces a 5-10 minute attribution gap on iteration start/stop; the explicit reload makes the new state visible to MV writes within milliseconds. (from: experimentation_full_20260521, 2026-05-22)
- **First-exposure via inverted version on ReplacingMergeTree:** `ReplacingMergeTree(_version)` keeps the row with MAX `_version` during merges. To get FIRST-exposure semantics (MIN timestamp), store `-toUnixTimestamp64Milli(evaluated_at)` as `_version` — MAX of the negated values is the MIN of the original timestamps. Pair with `OPTIMIZE TABLE ... FINAL` in tests for deterministic merges. (from: experimentation_full_20260521, 2026-05-22)
- **Per-context-type stats result shape — keyed map, not flat list:** When an experiment can target multiple `unit_context_types`, the results API returns `HashMap<context_type, Vec<VariantResult>>` rather than a flat `Vec<VariantResult>`. Flat list with a context_type column on every row is tempting but inflates payload + makes context-type-scoped operations (SRM per context type, guardrail per context type) require a GROUP BY at every read site. The keyed map matches the UI's tab-strip-per-context-type rendering 1:1. (from: experimentation_full_20260521, 2026-05-22)
- **Sentinel-prefix message for cross-service typed errors over `tonic::Status`:** Adding a structured HTTP 409 (with the locking experiment ID) to the gateway without touching protobuf: encode the typed information into the `Status::failed_precondition` message via a stable prefix (`flag_locked_by_experiment:<uuid>`). The gateway's `From<tonic::Status>` checks the prefix BEFORE the generic `FailedPrecondition → Conflict` mapping. Cleaner than `tonic::Status::with_details(Any)` for one-off cases and keeps the gRPC-typing surface minimal. (from: experimentation_full_20260521, 2026-05-22)
- **CH migration `--`-comment stripping must precede `;`-split:** Embedded migration runners that split SQL on `;` to execute statement-by-statement must first strip `--`-line comments, or a SQL comment containing a semicolon (e.g. `-- foo; bar`) gets split mid-comment and the second half hits CH as an invalid statement. The stripping must be line-based, not regex-global, to preserve `;` inside string literals. (from: experimentation_full_20260521, 2026-05-22)
- **`cardinality(arr) > 0` over `array_length(arr, 1) >= 1` for PG non-empty CHECK:** `array_length(arr, 1)` returns `NULL` for empty arrays, and PG `CHECK` treats `NULL` as passing — so the constraint silently allows `{}` input. Always use `cardinality(arr) > 0` for non-empty enforcement on `text[]` / `UUID[]` / etc. columns. (from: experimentation_full_20260521, 2026-05-22)
- **Closure-injected lookups in route validators (no gRPC mocks):** Route validator functions that depend on cross-service RPCs should accept generic async closures for the lookups: `fn validate_foo<F, FFut, G, GFut>(input, flag_lookup: F, ctx_lookup: G)` where `F: Fn(...) -> FFut`. Unit tests stub them with plain `|_, _| async { Ok(...) }` — no need for tonic mock servers. Production callers pass a thin wrapper that clones the `GatewayState` `Arc` into the closure and awaits the real RPC. (from: experimentation_full_20260521, 2026-05-22)
- **Beads `bd close --no-auto` doesn't reliably persist phantom-dep closures — use plain `bd close`:** During parallel-wave development, `--no-auto` may leave the dependency edge in a state where re-running `bd ready` re-claims the just-closed task. Use plain `bd close <id>` and add `--force` only when the issue has a phantom dependency that's already been satisfied (e.g. on cleanup at end of phase). (from: experimentation_full_20260521, 2026-05-22)
- **Per-flag (not per-rule) uniqueness for active-experiment lock:** When the lock model is whole-flag-while-running (vs. per-rule), the PG partial unique index must move with it: `idx_experiments_one_active_per_flag` on `(flag_id) WHERE status IN ('running','paused')`. The `UniqueViolation { field }` returned by sqlx then reports `flag_id` instead of `flag_rule_id` — test assertions on the field name must update. (from: experimentation_full_20260521, 2026-05-22)
- **CH `arrayExists()` in JOIN ON breaks under both analyzers — use ARRAY JOIN first:** ClickHouse 24's legacy analyzer rejects `INNER JOIN ... ON arrayExists(...)` with `INVALID_JOIN_ON_EXPRESSION`; the new (experimental, future-default) analyzer accepts it but loses joined-table column qualification (`Not found column __table2.context_type`). Restate as `ARRAY JOIN contexts AS t` to unfold the array, then a plain equi-join on the unfolded columns. Same semantics, works under both analyzers. (from: experimentation_full_20260521, 2026-05-22)

## Docs Autogeneration Patterns

- **Single-command doc pipeline with idempotency CI gate:** `cargo xtask docs` runs every doc generator + mdbook build + internal-link check in one shot. The CI `docs-build` job runs it, then `git diff --exit-code` — any drift between source-of-truth and committed output fails the build. Forces "edit the source, not the artifact" discipline without runtime gating. Steps must order: rustdoc-copy AFTER mdbook build (mdbook clears its build dir on rebuild). (from: docs_refresh_20260522, 2026-05-22)

- **Env-var doc generator via paren-depth-aware Rust scanner:** A plain text-scan-and-grep approach to extracting `env::var("PREFIX_X")` + `env_or("PREFIX_X", "Y")` call sites breaks on multi-line chains and accidentally captures defaults from sibling statements. Fix: bound the chain window with `find_statement_end()` that tracks paren depth + skips string-literal contents, terminating at the first `;`/`,`/`}` at depth 0 (NOT a fixed character count). Also: when the default is an identifier (`.unwrap_or(DEFAULT_PORT)`), resolve via in-file `const DEFAULT_PORT: ... = LIT;` lookup before giving up — most projects use named consts for port defaults. (from: docs_refresh_20260522, 2026-05-22)

- **`cargo-rdme` with markers preserves rich READMEs:** Default `cargo-rdme` replaces the entire `README.md` with the rendered `//!`. To keep existing rich content (Module tables, code samples, etc.), add a single `<!-- cargo-rdme -->` marker line where the generated content should land. On first run, cargo-rdme replaces the marker with `<!-- cargo-rdme start --> ... <!-- cargo-rdme end -->` and inserts content between; on subsequent runs only the between-region updates. Marker placement convention: right after the `# <crate>` H1, with the legacy one-paragraph summary stripped (the `//!` IS the summary now). (from: docs_refresh_20260522, 2026-05-22)

- **`cargo-rdme --workspace-project` uses `package.name`, not directory name:** `sdks/rust/` is the directory but `stitchd-sdk-rust` is the package name. The flag takes the package name. When iterating workspace members in an xtask, hardcode the package names (build them from `cargo metadata --format-version=1` if dynamic discovery is needed; static `const SLICE` is fine for stable membership). (from: docs_refresh_20260522, 2026-05-22)

- **In-xtask link checker over mdbook-linkcheck:** `mdbook-linkcheck` 0.7.x is incompatible with mdbook 0.5.x (RenderContext schema drift: `missing field 'sections'`). A custom in-xtask walker is ~80 LOC, faster, and deterministic: walk every `.md` under `docs/src/`, extract `[text](dest)` + reference-style `[label]: dest`, skip URL schemes, resolve relative to the linking file's parent, normalize `./` and `../` while preserving leading-`/` for absolute paths, and treat `.html` as also-OK if a matching file exists under `docs/book/` (so post-mdbook-build rustdoc cross-refs like `../rustdoc/index.html` resolve). Report ALL broken links before failing — not first-only. (from: docs_refresh_20260522, 2026-05-22)

- **xtask step ordering: cargo-doc AFTER mdbook-build:** `mdbook build` clears its `build-dir` on every rebuild. Any cargo-doc artifact copied into `docs/book/rustdoc/` BEFORE mdbook build will be silently wiped. Always copy rustdoc AFTER mdbook completes. Easy mistake to make because the rest of the pipeline reads "build the docs first, then the book" — the inversion catches you. (from: docs_refresh_20260522, 2026-05-22)

## Schema Cutover Patterns

- **sqlx composite type array columns require `PgHasArrayType`:** When implementing `sqlx::Type + Encode + Decode` for a custom Postgres composite type that is stored as an array column (`type_name[]`), you must also implement `sqlx::postgres::PgHasArrayType` — without it sqlx cannot infer the array element OID and queries against that column fail at runtime. (from: schema_cutover_20260525, archived 2026-05-25)

- **Circular FK in Postgres (e.g. parent ↔ child): use deferred ALTER TABLE:** When two tables reference each other (e.g. `feature_flags.default_variant_id → variants(id)` and `variants.flag_id → feature_flags(id)`), create the parent table *without* the back-reference column, create the child table with its FK, then `ALTER TABLE parent ADD COLUMN IF NOT EXISTS back_ref UUID REFERENCES child(id)`. This is the only safe DDL ordering — trying to inline both FKs in CREATE TABLE always fails. (from: schema_cutover_20260525, archived 2026-05-25)

- **Migration baseline synthesis: `IF NOT EXISTS` throughout, drop-aware:** When collapsing N incremental migrations into a single V1 baseline, use `CREATE ... IF NOT EXISTS` on every DDL statement so the baseline is idempotent. More importantly, if a later migration drops an object that an earlier one created, *omit both* from the baseline — fresh deployments never see either. Tables retired by the cutover (e.g. `segment_rules`) must not appear. (from: schema_cutover_20260525, archived 2026-05-25)

- **Basis Points Rollout Precision:** Rollout allocations use integer basis points (`u32` where 1 = 0.01% precision, 10000 = 100%) rather than float percentages (`f64`). This allows exact integer validation (no floating-point epsilon/sum tolerance needed) and matches DB storage directly. (from: schema_cutover_20260525, archived 2026-05-25)

## Domain-Boundary Refactor Conventions
*(from: domain_boundaries_20260530, 2026-05-30)*

- **Gateway = pure REST↔gRPC translation + cross-cutting + orchestration, ZERO domain logic.** Gateway routes may parse/validate request *shape*, call service(s), map responses, and translate errors. They may NOT contain business rules, domain mapping, inline evaluation/hashing, or query-building. Cross-cutting concerns that DO belong in the gateway: JWT/SDK-key auth middleware, permission guards, rate-limit/quota, request tracing, `x-env-id` metadata injection, HTTP-status translation, pagination-param normalization. (Worked example: Phase 2 moved variant/boolean/segment-condition validation, experiment-binding validation, `_test` stamping, name/org_role defaulting, and read-modify-write metadata preservation out of the gateway into owning services.)

- **Server-side defense-in-depth + gateway fast-fail is the one allowed validation duplication.** A business-rule validation may live in BOTH the gateway (fast-fail for UX, better error messages) AND the service (authoritative, defense-in-depth) — but ONLY when documented as such. Default is service-only. `validate_hash_inputs` is the canonical example (gateway pre-flight + flag-service `validate_proto_hash_inputs`).

- **Partial-update via `optional` proto scalar, not read-modify-write in the gateway.** To preserve a field when a caller omits it, add an `optional` proto field (e.g. `MutateFlagRequest.enabled_override`) and let the service merge — never pre-fetch in the gateway to fill it in. For replacing a sub-entity while preserving siblings, add a dedicated `MutationKind` (e.g. `REPLACE_VARIANTS`, `REPLACE_RULES`) so the service does the fetch-merge atomically.

- **Cross-domain access is gRPC-only; service crates never import sibling service crates at runtime.** A service depends on `stitchd-core` (pure primitives), `stitchd-db` (shared repos), `stitchd-proto`, and `stitchd-event-writer` — never another `*-service` crate. Dev-deps on a sibling service for shared test utilities are tolerated only when explicitly documented. (Audit found analytics→stats as the one HIGH violation; the fix is a new `StatsService` RPC, not a crate import.)

- **`stitchd-core` is no-I/O.** Pure domain types and rule-engine logic only. No database, no network, no auth-protocol crypto with I/O. If something in core pulls `reqwest`/`argon2`/`openidconnect`, it belongs in the owning service.

- **Canonical `RepositoryError` → `tonic::Status` mapping.** `NotFound→not_found` · `VersionConflict→aborted` · `UniqueViolation→already_exists` · `ForeignKeyViolation→invalid_argument("referenced entity does not exist: {constraint}")` · `InvalidState→failed_precondition(reason)` · `Database|Unexpected→internal`. Version-conflict message is exactly `"version conflict: expected {e}, actual {a}"`. Prefer a typed `{ServiceName}Error` enum in `error.rs` (`impl From<RepositoryError>` + `impl From<…> for Status`) over ad-hoc per-handler `map_err` closures; `stitchd-db` also offers `impl From<RepositoryError> for tonic::Status` behind `feature = "tonic"`. One approved exception: revoke-last-SDK-key maps `UniqueViolation→failed_precondition` with a call-site comment.

- **REST pagination is always `page`+`per_page` (1-based) → `PaginatedResponse<T>` (`{items,total,page,per_page}`).** Use the shared `PaginationParams`/`PaginatedResponse` from `gateway::pagination`; never invent a bespoke `{offset,limit}` response envelope. Internal CH-backed list RPCs may use `offset`+`limit` at the proto level — the gateway translates `page`/`per_page` → `offset`/`limit`.

- **Proto field conventions.** New/migrated protos use `string created_at` (RFC 3339 UTC), not `int64 *_ms`. Optimistic-lock version fields are `uint64 version`. Admin CRUD uses separate `Create`/`Update`/`Delete` RPCs; `Mutate*` (single RPC, `MutationKind` discriminator) is reserved for the SDK-sync path (flags, segments SDK).

- **Consolidate shared helpers to their canonical home.** `hash_sdk_key` → `stitchd-core::auth::crypto`. Test-only ClickHouse seed rows → `SeedEventRow` in `stitchd-event-writer` and `SeedAssignmentRow` in `stitchd-db::clickhouse` (both behind `#[cfg(any(test, feature = "test-fixtures"))]`; sibling test crates enable the `test-fixtures` feature in dev-deps). Forwarding enum-as-string fields the gateway doesn't own (e.g. metric `aggregator`/`goal_direction`) should pass through verbatim, NOT be re-validated against an exhaustive match that breaks when the owning service adds a variant.

- **Cross-gRPC error sentinels are decoded centrally, never via per-route string matching.** When a service must signal a structured error class the gateway maps to a non-default HTTP body (e.g. `flag_locked_by_experiment:`, `invalid_distribution:`), define a shared `pub const …_STATUS_PREFIX` in the service's `error.rs`, mirror it in the gateway, and decode it in `GatewayError::from(tonic::Status)` — not with an inline `s.message().starts_with(...)` in one handler. (GL-06 brought `invalid_distribution` to this pattern.)

- **UI-shape ⇄ domain-shape translation is the gateway's JOB, not a leak.** Converting a UI-friendly wire shape (a flat sub-context list, a presentation DTO) into the canonical domain type (`EvaluationContext` bundle) belongs in the gateway. Do NOT push the admin UI's flat `_type`/`key` format into a domain service's gRPC API — that couples the service to a presentation concern and worsens boundaries. (Why GL-07's request-side restructure was a WONT-FIX.)

- **Deserialize opaque-JSON-over-gRPC into the canonical core type, don't hand-pick `Value`.** When a gRPC response carries a JSON-serialized core type as a `string` (e.g. `EvaluatePreviewResponse.results_json` = `Vec<ContextPreviewResult>`), the consumer should `serde_json::from_str::<TheCoreType>()` and map the typed struct → DTO, NOT walk `v["field"].as_u64().unwrap_or(0)`. Both ends share `stitchd_core`, so this is type-safe at compile time. A full proto-message mirror is only worth it when the payload is flat/static — recursive trees (`ConditionNode`) or arbitrary-JSON fields (`variant_value`) need `google.protobuf.Value` anyway, so the string-wire stays acceptable.

## Verification & CI Gotchas
*(from: domain_boundaries_20260530, 2026-05-30)*

- **DB-gated tests are invisible to the offline gate — run a live stack before merge.** `#[sqlx::test]` and ClickHouse-backed tests are skipped/failed-as-infra when no DB is up, so a contract/message change (e.g. normalizing a `version conflict` string, INCON-E005) can pass `cargo test` offline yet break a DB-gated assertion. Bring up Postgres + ClickHouse + ScyllaDB (`docker compose up postgres clickhouse scylladb -d --wait`) and run `cargo test --workspace --no-fail-fast` before declaring green.

- **Regenerate the sqlx cache with the SAME flags CI's `--check` uses.** CI runs `cargo sqlx prepare --workspace --check -- --all-targets --features stitchd-sdk-rust/test-util`. Regenerating with only `-- --tests` can drop entries that compile under `--all-targets`/the test-util feature, and `--check` then fails in CI. After dropping/adding any `query!`/`query_scalar!` (e.g. PROP-001's `frozen` column removal), regenerate against a live DB and re-run the exact `--check` command locally.

- **The live-ClickHouse stats tests are guarded by a SEPARATE CI step with an EXPLICIT `--test` list — keep it in sync.** `cargo llvm-cov` (the Coverage job's main pass) does NOT run `#[ignore]`d tests, so the self-seeding live-CH integration tests in `stitchd-stats-service` (`aggregation_query`/`ratio_query`/`funnel_query`/`preview_query`/`interaction_compute`/`compute_pass`/`cuped_compute`/`percentile_significance`) run in a dedicated *"Live-ClickHouse integration tests (stats-service)"* step that names each `--test` target by filename and passes `-- --ignored`. Renaming/removing one of those `tests/*.rs` files without updating the step makes cargo exit 101 (`no test target named X`) → the Coverage job and all of CI go red on the NEXT push, and it is **invisible to local `cargo test --workspace`** (which never runs the step). The N-way rename (`interaction_query`→`interaction_compute`) left a stale target that reddened CI from the nway merge through the seqtest merge until `cce4819` rebuilt the full 8-target list. Same root family as the `event_writer::migrations` hardcoded-`include_str!`-array gotcha: a hardcoded list that a file rename silently desyncs. (from: nway_interaction_20260603 + seqtest_20260603, 2026-06-04)

## Cross-Experiment Interaction Patterns (from: xexp_interaction_20260602, 2026-06-02)

- **Keep `evaluate_flag` experiment-unaware by riding new gates on the rule, not the experiment.** The exclusion gate is `RuleOutput::Percentage.exclusion_gate: Option<ExclusionGate>` — static snapshot data persisted inside `feature_flag_rules.rule_def` JSONB (round-trips for free via serde). The flag read path (`find_rules`) needed NO change; the experimentation-service stamps/clears the gate via a small `set_rule_exclusion_gate` repo method. Result: gating is pure, in-memory, zero-DB-lookup, and `evaluate_flag` never learns about experiments. (from: xexp_interaction_20260602)
- **Adding a field to a widely-constructed enum/struct ripples across crates.** `RuleOutput::Percentage`/`Experiment` are constructed at ~28+ sites across 9 crates. Add the field with `#[serde(default, skip_serializing_if=...)]` for storage back-compat, then mechanically thread `None` / add `..` to every construction/match site until `cargo build --workspace --all-targets` is green. Budget a dedicated sweep task for this. (from: xexp_interaction_20260602)
- **ClickHouse `FINAL` modifier follows the alias:** write `experiment_assignments AS a FINAL`, NOT `experiment_assignments FINAL AS a` (the latter is rejected). Caught by a live-ClickHouse integration test, not the builder snapshot. (from: xexp_interaction_20260602)
- **Reuse the existing distribution helpers in `stitchd-core::experimentation::stats`.** `srm.rs::chi_square_sf` (incomplete-gamma series) is reusable for chi-square interaction tests; add an F-distribution survival via the regularized incomplete beta for two-way ANOVA. Bump visibility to `pub(crate)` rather than duplicating. (from: xexp_interaction_20260602)
- **ClickHouse Float64 can't store NaN cleanly:** persist insufficient-data interaction results as `0.0` with `significant=false`; consumers must check an explicit insufficient-data/`significant` flag, never sniff NaN. (from: xexp_interaction_20260602)
- **New ClickHouse migrations must be added to the `event_writer::migrations` MIGRATIONS array** (`include_str!`) — the runner uses a hardcoded list, not a directory glob, so a file dropped in `migrations/` is silently never applied on boot. (from: xexp_interaction_20260602)

## N-Way Interaction / Parallel-Stats Patterns (nway_interaction_20260603)

- **clickhouse-rs (`clickhouse` 0.15) maps `#[derive(Row)]` columns by NAME, not position.** A `SELECT … AS alias` must match the struct field name. Corollary gotcha: you cannot alias a projection back to a source column's name when that column is referenced (different type) in `WHERE`/`ORDER BY` — `SELECT arrayMap(x->toString(x), experiment_ids) AS experiment_ids … WHERE has(experiment_ids, …)` fails with `NO_COMMON_TYPE` (String[] alias vs UUID[] column). Alias to a distinct name (`experiment_ids_str`) and name the struct field to match. (from: nway_interaction_20260603)
- **`Array(UUID)` has no built-in serde in clickhouse 0.15** (only scalar `clickhouse::serde::uuid`, which encodes as a `(u64,u64)` pair in RowBinary). For array columns write a tiny module that (de)serializes `Vec<Uuid>` as `Vec<(u64,u64)>` via `Uuid::as_u64_pair`/`from_u64_pair` — byte-compatible with the scalar element encoding. Writer and reader must use the SAME encoding; verify with a live-CH round-trip test (unit/shape tests won't catch it). (from: nway_interaction_20260603)
- **Parallel worker-wave for a pure-stats module:** carve the module into a *seam* (shared contract types + `pub(crate)` distribution helpers + flat `pub use` re-exports over private submodules, each a stub file) committed FIRST by the orchestrator, then one worker per disjoint submodule file. Zero merge conflicts because each worker owns exactly one new file; the orchestrator owns the seam + reconciliation. Used here for 5 stats families (loglinear/anova/ratio/bayes_binary/bayes_continuous). (from: nway_interaction_20260603)
- **Generalize-without-breaking-regression:** when generalizing pairwise→N-way, have the order-2 / 2-way term **delegate to the existing pairwise function** (collapse the k-D grid onto the 2 factors and call it) so behavior is bit-for-bit identical by construction; only the genuinely-new terms (main effects, 3-way) get fresh math. Assert the equivalence in an integration test. The legacy fns stay (load-bearing), so "retire legacy" means retiring the old *sweep/orchestration path*, not the leaf math. (from: nway_interaction_20260603)
- **Deterministic Bayesian summaries (no RNG):** a linear-contrast posterior over independent cells is `Normal(Σ coef·mean, Σ coef²·var)` — Beta(α,β) moments for binary, sample-variance/n for continuous, delta-method var for ratio. Report `prob = Φ(|E|/sd)`, `expected = E`, CI `= E ± 1.96·sd`. Closed-form ⇒ bit-identical across runs (RNG is banned in `stitchd-core` stats — it would break determinism + resume). (from: nway_interaction_20260603)
- **Triple enumeration uses Helly's theorem (1-D):** for active-window overlap, pairwise overlap of intervals implies a common intersection, so a 3-way candidate only needs all three *pairs* valid + a metric common to all three (`a∩b∩c`) — no separate triple-window check. (from: nway_interaction_20260603)
- **Run a live-CH `--ignored` integration test before declaring a CH schema/serde change done.** The writer↔reader round-trip (Array(UUID) encoding, alias collisions, `FINAL` semantics) is only exercised against a real ClickHouse; `cargo test` skips `#[ignore]`d tests by default — run `-- --ignored` with `STITCHD_CLICKHOUSE_*` set. (from: nway_interaction_20260603)
- **A new query builder for an existing metric kind MUST be derived from the canonical builder** (`queries::{aggregation,ratio,funnel}`), not written fresh. The interaction builders diverged and independently dropped the JsonLogic `where_clause`, fanned out the ratio via a double `LEFT JOIN` (the canonical ratio query pre-aggregates each leg to one value per `(context,variant)` before a 1:1 join precisely to avoid this), and mis-aliased a column. Reuse the canonical CTE shape + helpers; a metric filter silently ignored = every cell computed over the wrong event set. (from: nway_interaction_20260603, review)
- **A ReplacingMergeTree dedup `ORDER BY` must contain the FULL natural key.** Omitting a key column (here `experiment_ids`) silently collapses distinct rows that happen to share the remaining columns, under `FINAL`. `Array(UUID)` is allowed in a sort key — verify with a live `CREATE`. In-memory fake-writer unit tests are blind to this; only a live-CH FINAL round-trip catches it. (from: nway_interaction_20260603, review)
- **Don't let "context" rows pollute a multiplicity-corrected family or a page-level warning.** Emitting single-experiment main-effect rows alongside interaction terms inflated the Benjamini-Hochberg family (shifting the interaction step-up threshold) and fired the UI "interaction detected" banner on every well-powered experiment. Scope the corrected family + the warning gate to the terms they're actually about; never gate a page-level warning on an UNcorrected directional Bayesian prob (`Φ(|E|/sd)` ≈0.5 under the null). (from: nway_interaction_20260603, review)
- **Consolidate N per-item self-join queries into one via a shared-base CTE + per-grid `UNION ALL` with a discriminator.** The sweep issued C(k,2)+C(k,3) independent `experiment_assignments FINAL` scans per (metric, context); one query with a single shared FINAL scan + per-tuple aggregation branches (tagged by a `tuple_idx`) cut it 4→1 for k=3 (combinatorially more for larger k). Guard the rewrite with an equivalence test asserting the consolidated rows are field-identical to the per-item rows. (from: nway_interaction_20260603, review/ef5)

## Sequential Testing & Live Stats Compute Patterns (seqtest_20260603)

- **ClickHouse query-builder bind order MUST equal the textual `{pN}` appearance order.** `dispatch::rewrite_placeholders_to_clickhouse` replaces every `{pN}`→`?` in TEXT-scan order (the integer N is parsed but IGNORED) and `bind_query` binds the `binds` Vec positionally — so push order must match where each placeholder appears in the assembled SQL. A CTE reorder that pushes a later-appearing bind earlier silently cross-binds the WHOLE query (a funnel step key `'view'` landed in the `toUUID(env_id)` slot → every funnel query errored). Guard every builder with a bind-order test (placeholders strictly ascending) + a `debug_assert` in the rewriter. (from: seqtest_20260603, review)
- **Don't overload a `variant_key → value` JSON map with object "sideband" payloads.** The compute pass stashed `srm`/`cuped` blobs under reserved keys in the `variant_stats` map that the read iterates as variants; the read MUST skip by VALUE TYPE (`val.is_object()`), not a hardcoded key-name, or each new sideband leaks as a phantom zero-count variant in the API. A dedicated proto/column field is the deeper fix. (from: seqtest_20260603, review)
- **SECURITY — validate AND escape admin-controlled field names in CH SQL.** Metric `on_field` + JsonLogic `{"var": …}` names are string-interpolated into `properties['<field>']` (not bindable), and `AggregationConfig::validate()` was a no-op → SQL injection. Reject `' \ { } [ ]` at config validation (the `{`/`}` also prevent `{pN}` placeholder-collision) AND `clickhouse_escape` at EVERY interpolation site — there were FOUR incl. the `Uniq` aggregator's `on_field_expr`; grep `properties['{` exhaustively, a sibling site is easy to miss. (from: seqtest_20260603, review)
- **Single-source the stats math in `stitchd-core`.** One `pub(crate)` `erf`/`norm_cdf`/`Z95`(=Φ⁻¹(0.975)=1.959964)/`ratio_delta_var`; every engine (frequentist/bayesian/sequential/interaction) delegates, pinned by bit-identity tests so a future tweak can't silently diverge one path. mSPRT / likelihood ratios are computed in LOG space (`ln_lambda` then `exp(-ln_lambda)`) — direct `lambda` overflows to +∞ for strong effects and spuriously collapses a significant look to insufficient-data. (from: seqtest_20260603)
- **ITT per-metric sufficient stats:** `sample_size` = assigned-unit count from `experiment_assignments` (the ITT denominator; a LEFT JOIN zero-fills non-firing units), successes/sums from the event-join. `analyze_numeric/count/funnel` MUST guard `n<2`/`n<1` → insufficient, else Welch df = `0/0 = NaN` → `t_to_p(NaN)=0.0` → a 1-unit arm is reported as a significant winner. The single-variant sufficient-stats SQL specializes the N-way `interaction_metric.rs` cells. (from: seqtest_20260603, review)
- **SRM expected split = the experiment's CONFIGURED allocation, not uniform 1/K.** Source per-variant weights from `default_rule_distribution` (default-rule experiments) or the bound rule's percentage allocation, normalize within the experiment's variants, and zero-fill configured-but-absent arms (else a 95/5 canary reads false-RED under a uniform null, and a totally-starved arm is invisible). (from: seqtest_20260603, review)
- **A "deferred to a later phase" scaffold can sit in `main` looking complete.** The scheduled per-metric stats compute was `write_results(exp, &[])` (empty summaries) with NO service calling any `stitchd-core` stats fn — yet the storage/read/UI all existed, so the engine LOOKED done. Grep for actual call sites (`frequentist::`/`bayesian::`/`cuped`/`srm`) before trusting a "✅ complete" module to produce live values. (from: seqtest_20260603)
- **A backgrounded `cargo test … | tail` masks the real exit code** (the pipeline's exit is `tail`'s, not cargo's) AND truncates the log. Re-run to a full logfile with `; echo $?` (zsh: `$?`, NOT `${PIPESTATUS[0]}`) to get a conclusive pass/fail total. (from: seqtest_20260603)
- **Cross-service domain errors are sentinel-STRING-prefixed tonic statuses, not a proto enum.** There is no proto error enum in this tree. A 409-class domain error is a `Status::failed_precondition` whose message starts with a `pub const … _PREFIX` (e.g. `flag_locked_by_experiment:`, `dependency_exists:`), decoded in `crates/stitchd-gateway/src/error.rs` into a structured `GatewayError` → HTTP 409. Each producing service holds its OWN private copy of the const (no shared const crate); the gateway decode is source-agnostic, so a new producer needs NO gateway change. Add new domain errors this way. (from: flag_lifecycle_20260604)
- **A new crate breaks the `cargo xtask docs` idempotency CI gate unless wired in.** cargo-rdme does NOT create a README; a new crate must be added to xtask's `CRATE_README_TARGETS` and given a README marker, then `cargo xtask docs` fills it from the crate's `//!` preamble. Workspace-wide CI jobs (fmt/clippy/sqlx-check/coverage) auto-cover a new `[workspace.members]` crate (no per-crate matrix), and `tests/e2e/*.yaml` picks up a new docker-compose service via `up --wait` — so the ONLY manual CI/docs wiring for a new service is its README target + docker-compose entry. (from: flag_lifecycle_20260604)
- **Build offline, test online — and never point `query!` at the drifted dev DB.** `cargo build`/`clippy` must use `SQLX_OFFLINE=true` (the committed `.sqlx/` cache); `#[sqlx::test]` needs `DATABASE_URL` at RUNTIME (it provisions a fresh ephemeral DB, sidestepping the shared dev DB's `_sqlx_migrations` baseline-checksum drift from sibling worktrees), so a test run sets BOTH. `STITCHD_DATABASE_URL` is NOT in the bare agent shell — `set -a; source .env.local; set +a`. Exporting an empty `DATABASE_URL` makes every `#[sqlx::test]` panic with `RelativeUrlWithoutBase`; pointing `query!` macros at the live drifted DB yields ~96 phantom compile errors. (from: flag_lifecycle_20260604)
- **Adding a field to a core aggregate (e.g. `Flag`) has a workspace-wide constructor blast radius.** Every full-struct literal across crates (flag-service, sdk, db, gateway mocks, tests) must set it; `#[serde(default)]` doesn't help struct literals. Use `cargo test --workspace --all-targets --all-features --no-run` (NOT just `build --workspace`) to surface feature-gated test targets before declaring a field-add green. (from: flag_lifecycle_20260604)
