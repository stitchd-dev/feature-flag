# OpenAPI Spec

The gateway publishes an OpenAPI 3.0 specification that describes every
REST endpoint, request schema, response schema, and security requirement.
It is generated from `#[utoipa::path]` annotations on every route handler
and committed to the repository so contributors don't need a running
gateway to inspect the contract.

## Viewing the spec

The generated spec is committed at `docs/src/api/openapi.json` and is
regenerated by `cargo xtask docs`.

To browse it interactively, run a local Swagger UI:

```bash
# Using Docker (point SWAGGER_JSON_URL at wherever you're serving the JSON)
docker run -p 8888:8080 \
  -e SWAGGER_JSON_URL=http://localhost:3000/api/openapi.json \
  swaggerapi/swagger-ui

# Then open: http://localhost:8888
```

Or paste the JSON into the public [Swagger Editor](https://editor.swagger.io/).

## Regenerating the spec

```bash
cargo xtask docs
```

The `docs` xtask:

1. Builds `stitchd-gateway` in debug mode.
2. Invokes `target/debug/stitchd-gateway --export-openapi docs/src/api/openapi.json`.
3. The binary serialises the `utoipa`-derived `ApiDoc` struct
   (`crates/stitchd-gateway/src/openapi.rs`) to pretty JSON and writes
   it to the path.

The spec is derived from `#[utoipa::path]` annotations on every route
handler under `crates/stitchd-gateway/src/routes/`. To add a new endpoint
to the spec:

1. Annotate the handler with `#[utoipa::path(...)]`.
2. Add the handler path to the `paths(...)` list in `ApiDoc` in
   `crates/stitchd-gateway/src/openapi.rs`.
3. Register any new request/response types in the `components(schemas(...))`
   block.
4. Run `cargo xtask docs` to regenerate.

## Contract checking

A repository script checks for REST contract drift between the gateway's
actual router and a frozen pre-decomposition snapshot:

```bash
python3 scripts/check_openapi_contract.py
```

The script:

- Parses `crates/stitchd-gateway/src/router.rs` for registered Axum
  routes (`.route(...)` plus method chains).
- Compares against the snapshot at `docs/openapi-pre-decomposition.json`.
- Reports any pre-decomposition route that disappeared from the router,
  excluding a small `KNOWN_GAPS` allowlist for routes whose URL shape
  legitimately changed during `boundaries_20260518`.

Run this in CI to catch accidental REST contract regressions before they
reach `main`. The script does not compare against `docs/src/api/openapi.json`
directly — that file is regenerated on every `cargo xtask docs` and is
inherently in sync with the handler annotations.

## Security schemes

The spec defines two security schemes, attached via the `security` field
on each endpoint:

| Scheme       | Type        | Header                               |
|--------------|-------------|--------------------------------------|
| `sdk_key`    | API Key     | `x-sdk-key`                          |
| `bearer_jwt` | HTTP Bearer | `Authorization: Bearer <jwt>`        |

Endpoints that need no auth (e.g. `POST /v1/auth/login`) declare an empty
security array. See [Gateway](./overview.md) for which routes use which
scheme.
